# 기간별 갱신

## 사용자 명령

```text
$naver-blog-update 2026-08
$naver-blog-update 2026-10
$naver-blog-update 2026-10-10
```

월 또는 일 하나를 KST 기준으로 명시합니다. 네이버 블로그를 검색의 목적지로 유지하는 정책이 매번 적용됩니다. 스킬은 예약 작업 자체를 생성하지 않습니다. 매일 한 달씩 과거 자료를 정리할 계획이라면 날짜가 다른 명령을 각 실행에 지정합니다.

## 수집 → 검토 → 적용 → 생성

1. `python3 scripts/sync_blog.py collect 2026-08`: 공개 제목 목록을 페이지 단위로 순회해 기간 경계를 확인하고 해당 글의 실제 본문을 가져옵니다. RSS 최신 글만 보고 과거 월의 전체를 판단하지 않습니다.
2. `.cache/blog-sync/2026-08/manifest.json`에서 new/changed/unchanged와 오류를 확인합니다. 스킬은 new/changed 본문과 해당 소개 JSON만 읽습니다.
3. 본문을 실제로 읽고 독립적인 소개를 작성해 manifest에 적힌 reviewFile 경로에 저장합니다. 이는 모델이 담당하는 검토 단계이며 수집 스크립트가 자동으로 요약하는 것은 아닙니다.
4. `python3 scripts/sync_blog.py apply 2026-08`: 모든 검토 항목을 검증한 뒤 ID별 JSON과 완료 보고서를 저장합니다. 미검토·불완전 수집을 성공으로 처리하지 않습니다.
5. `python3 scripts/build.py`, `python3 scripts/check.py`로 생성과 검증을 수행합니다.
6. `python3 scripts/sync_root_home.py --check`로 같은 저장소의 `index.html`과 `blog/index.html`이 일치하는지 확인합니다. 전체 배포 파일은 `blog/`에 생성되며 별도 저장소 복사는 필요하지 않습니다.

같은 기간을 재실행해 원문 해시가 같으면 소개문을 다시 작성하지 않고 기존 수정일과 파일을 유지합니다. 수집 요청의 네트워크 비용은 발생하지만 원문 전체를 모델에 매번 다시 넣을 필요는 없습니다.

## 보관 형식

`content/posts/2026/08/224394493363.json`처럼 게시월별 원문 ID 파일에 소개 원본을 저장합니다. 원문 날짜가 바뀌면 JSON 저장 위치는 바뀔 수 있지만 public slug와 개별 페이지 URL은 유지합니다. 원문 전문은 `.cache/`의 로컬 확인 자료로만 보관하며 Git에 포함하지 않습니다.

각 소개에는 확인한 제목·분류·게시 시각·원문 URL과 `sourceHash`를 기록합니다. `introUpdatedOn`은 소개를 실제로 검토한 날입니다. `sourceCheckedAt`은 당시 원문 확인 시각이며 이후 unchanged 확인 시각은 실행 보고서에 남겨 소개 수정일과 혼동하지 않습니다.

`content/sync-state.json`은 완료한 기간 목록입니다. 월 완료와 일 완료는 서로 다른 항목이며 하루를 확인했다고 월 전체가 완료되지는 않습니다. 비어 있는 기간도 공개 목록의 범위를 정상 확인한 경우에만 완료로 기록할 수 있습니다. 진행 중인 월·일의 완료 상태는 checkedAt 시점까지 확인했다는 뜻이며 그 이후 새 글까지 확인했다는 의미는 아닙니다.

## 실패와 경계

- 목록 페이지가 반복되거나 정렬·전체 개수가 수집 중 변하면 완전성을 주장하지 않고 재확인을 요청합니다.
- 대상 글에 접근할 수 없거나 본문·정확한 게시일이 없으면 이전 소개를 유지합니다.
- 기존에 해당 기간에 속하던 글도 다시 조회합니다. 날짜가 달라진 글은 변경으로 검토하되 임의 삭제하지 않습니다.
- 초 단위가 보이지 않는 날짜는 분 단위만 사용합니다. 최근 글의 상대 날짜는 가능한 경우 RSS의 정확한 게시 시각으로 확인합니다.
- 본문 텍스트·제목·분류·게시 시각의 변경을 판별합니다. 사진 교체나 이미지 내부 문구까지 확인했다고 주장하지 않습니다.
- 원문의 표·이미지·인용 자료에 접근하지 못했다면 소개에 그 한계를 기록합니다.

## 운영 범위

전체 HTML은 `noindex, follow`입니다. 공개 GitHub 페이지에 대한 사이트맵 제출이나 색인 요청은 실행하지 않습니다. 원문 링크와 출처는 네이버로 유지합니다. noindex가 네이버의 순위를 올려주는 것은 아니며 Google이 처리하기까지 시간이 걸릴 수 있습니다.

정기 실행을 별도로 설정할 때도 사용자에게 실행 날짜·주기·커밋/push 여부를 확인하고, 이 스킬의 원문 확인·검토 기준을 유지해야 합니다. 현재 스킬은 로컬 갱신을 끝내며 커밋·push를 자동으로 하지 않습니다.
